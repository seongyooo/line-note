## 기본 구조

**Base Station = AP (Access Point)**
- 유선 네트워크와 무선 호스트를 연결해주는 중계기
- 집에서 쓰는 공유기가 바로 AP

**BSS (Basic Service Set) = Cell**
- 하나의 AP + 그 AP에 연결된 무선 호스트들의 묶음
- 하나의 WiFi 커버리지 영역

| | Infrastructure Mode | Ad Hoc Mode |
|---|---|---|
| AP 존재? | ✅ 있음 | ❌ 없음 |
| 통신 방식 | 호스트 → AP → 목적지 | 호스트 → 호스트 직접 |
| 예시 | 일반 WiFi | 블루투스, 임시 네트워크 |

> ⚠️ **Wireless ≠ Mobile!**
> 무선이라고 항상 이동하는 건 아님. 데스크탑에 WiFi 카드 꽂아서 쓰면 무선이지만 이동하지 않음.

## Associate (연결) 과정 6단계

```
1. Channel Scan      → 여러 채널을 돌아다니며 신호 탐색
2. Beacon Frame      → AP가 주기적으로 자신의 존재를 알리는 신호 수신
3. SSID & BSSID 확인 → SSID = WiFi 이름 / BSSID = AP의 MAC 주소
4. AP 선택 (Select)  → 신호 강도, 보안 방식 등 고려
5. Authentication    → 비밀번호 확인 등 보안 절차
6. DHCP              → AP의 서브넷에서 IP 주소 할당
```

## Passive vs Active Scanning

### Passive Scanning (수동)
- AP가 **먼저** Beacon을 뿌림
- Host는 **듣기만** 하다가 마음에 드는 AP에 연결 요청
- 배터리 소모 적음

```
흐름: Beacon 수신 → Association Request → Association Response
```

### Active Scanning (능동)
- Host가 **먼저** Probe Request를 브로드캐스트
- 주변 AP들이 응답
- 더 빠르게 AP 찾을 수 있음 (숨겨진 AP도 탐색 가능)

```
흐름: Probe Request → Probe Response → Association Request → Association Response
```

## CSMA/CA

### 왜 CSMA/CD를 못 쓰나?
- 내가 강하게 쏘는 신호 때문에 약한 수신 신호를 **못 들음**
- Hidden Terminal Problem 존재
- → 충돌을 **감지(CD)** 하는 게 아니라 **방지(CA)** 하는 전략 사용

### 동작 과정
```
보내고 싶다!
    ↓
DIFS 동안 채널 idle?
    ↓
YES → 바로 전송 (전체 프레임)
NO  → Random Backoff 타이머 카운트다운
      (채널 idle일 때만 카운트)
      타이머 0 되면 전송
      ACK 없으면? → Backoff 범위 늘려서 재시도
```

### DIFS vs SIFS

| | DIFS | SIFS |
|---|---|---|
| 풀네임 | Distributed Inter-Frame Space | Short Inter-Frame Spacing |
| 길이 | 김 | 짧음 |
| 사용 시점 | 데이터 전송 **전** | ACK 전송 **전** |

> ACK가 필요한 이유 → **Hidden Terminal Problem** 때문!
> A와 C가 서로 못 들으면서 둘 다 B한테 보내면 B에서 충돌 발생

## RTS/CTS (Collision Avoidance)

Hidden Terminal Problem을 해결하는 더 강력한 방법

```
A          AP          B
|           |           |
|──RTS(A)──→|           |
|           |──CTS(A)──→|  ← B도 CTS 들음!
|           |           |
|           |    [B는 defer, 대기]
|                       |
|────────DATA───────────→|
|←──────────ACK──────────|
```

- **RTS**: 짧은 패킷 → 충돌해도 낭비 적음
- **CTS**: AP가 브로드캐스트 → 모든 노드가 들음
- CTS 들은 노드들은 자동으로 전송 미룸 (defer)

## Rate Adaptation

### 기본 원리
- 멀어질수록 SNR ↓ → BER ↑
- BER이 너무 높아지면 → 낮은 속도, 낮은 변조 방식으로 전환

```
[AP 가까이] SNR 높음 → QAM256 → 8Mbps
    ↓ 이동
[중간 거리] SNR 중간 → QAM16  → 4Mbps
    ↓ 이동
[AP 멀리]  SNR 낮음 → BPSK   → 1Mbps
```

> 속도는 느려지지만 **연결은 유지**됨!

## Frame Addressing

WiFi는 AP를 거치기 때문에 주소가 3개 필요

```
[H1] ──무선──→ [AP] ──유선──→ [R1] ──→ 인터넷
```

| 주소 | 누구? | 역할 |
|---|---|---|
| Address 1 | AP | 이 프레임 받을 사람 |
| Address 2 | Host (H1) | 이 프레임 보낸 사람 |
| Address 3 | Router (R1) | AP가 유선으로 보낼 다음 목적지 |

## Power Management

```
Node → AP: "나 잘게요 (sleep 모드)"
AP: 이 노드한테 온 프레임 쌓아둠
AP가 Beacon 전송할 때: "이 노드한테 프레임 있음!" 포함
Node: Beacon 직전에 깨어남
    ├─ 프레임 있으면 → 깨어서 받음
    └─ 프레임 없으면 → 다시 잠듦
```

## Mobility Within Same Subnet

- 같은 서브넷 안에서 AP를 바꿔 이동할 때 **IP 주소는 그대로 유지**
- Switch의 **Self-learning**으로 자동 처리
  - H1이 AP2를 통해 프레임 보내면 Switch가 자동으로 경로 업데이트

## Bluetooth (Personal Area Network)

| 항목 | 내용 |
|---|---|
| 범위 | 10m 이내 |
| 주파수 | 2.4 GHz ISM 대역 |
| 최대 속도 | 3 Mbps |
| 구조 | Master 1개 + Client 최대 7개 |
| 모드 | Ad hoc (인프라 없음) |

- Master가 **polling** 방식으로 클라이언트 제어
- 79개 채널을 무작위 순서로 바꾸며 전송 (Spread Spectrum)
- **Parked Mode**: 배터리 절약을 위해 sleep 상태 전환 가능
